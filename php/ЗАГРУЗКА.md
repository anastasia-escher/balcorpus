# Как загружать корпус на сервер

Простыми словами: что один раз настроить, и что делать каждый раз, когда
приходит новый текст.

> **Важно:** PHP-часть ещё не написана. Это описание того, что мы сделаем, —
> и одновременно спецификация, по которой я буду писать код. Команды ниже
> заработают, когда файлы появятся.

Сервер: `languagesofthebalkans.whp.uzh.ch`
Заходить: `ssh languagesofthebalkan_hexru0kbt4j@130.60.247.23`

---

## Что где лежит на сервере

Две папки рядом друг с другом. Разница между ними важная:

```
httpdocs/          ← это видно из интернета
private/           ← это из интернета не видно
```

Всё, что не должно быть доступно посторонним — пароль от базы, данные для
загрузки, сам код бэкенда — лежит в `private/`. Наружу торчат только четыре
маленьких файла, которые отвечают на запросы.

Полная картина:

```
httpdocs/
  index.html                    сайт (сборка Nuxt)
  _nuxt/                        его стили и скрипты
  texts/index.html              страница со списком текстов
  api/v1/
    texts/index.php             отдаёт список текстов
    tokens/search/index.php     поиск
    sentences/index.php         предложения одного текста
    sentences/context/index.php контекст вокруг находки

private/
  config.php                    доступы к базе — ТОЛЬКО здесь
  db.php                        подключение к базе
  processing/                   логика поиска и сборки предложений
  sql/
    schema.sql                  создание таблиц
    import.php                  загрузчик CSV в базу
  data/                         сюда кладём файлы из php_ready
    speakers.csv
    texts.csv
    text_authors.csv
    sentences/<text_id>.csv
    tokens/<text_id>.csv
```

Почему адрес `httpdocs/api/v1/texts/index.php` отвечает на `/api/v1/texts/`:
если в папке лежит файл `index.php`, сервер отдаёт его, когда запрашивают саму
папку. Поэтому никаких дополнительных настроек не нужно, и адреса остаются
ровно такими, какие уже ждёт сайт.

## Один раз: первоначальная настройка

### 1. Создать базу

В панели Plesk: **Базы данных → Добавить базу данных**. Имя любое, пользователя
Plesk создаст сам с приставкой `whp_`, пароль — кнопкой **Generate**.
Пароль сразу сохранить, второй раз его не покажут.

### 2. Создать папки на сервере

Зайти по SSH и выполнить:

```
mkdir -p private/data/sentences private/data/tokens
mkdir -p httpdocs/api/v1/texts
mkdir -p httpdocs/api/v1/tokens/search
mkdir -p httpdocs/api/v1/sentences/context
```

### 3. Записать доступы к базе

Создать файл `private/config.php` с данными из шага 1. Пароль живёт только
здесь, больше нигде — ни в других файлах, ни в git.

### 4. Залить PHP-файлы

С локального компьютера, из папки проекта:

```
scp -r php/private/* languagesofthebalkan_hexru0kbt4j@130.60.247.23:private/
scp -r php/httpdocs/* languagesofthebalkan_hexru0kbt4j@130.60.247.23:httpdocs/
```

### 5. Создать таблицы

По SSH:

```
mysql -h mariadb.uzh.ch -P 3310 -u whp_ПОЛЬЗОВАТЕЛЬ -p ИМЯ_БАЗЫ < private/sql/schema.sql
```

Если команды `mysql` на сервере нет — то же самое через **phpMyAdmin** в
панели: открыть базу, вкладка «Импорт», выбрать файл `schema.sql`.

### 6. Собрать и залить сайт

Локально:

```
cd ui/app
NUXT_PUBLIC_API_BASE_URL=https://languagesofthebalkans.whp.uzh.ch yarn generate
scp -r .output/public/* languagesofthebalkan_hexru0kbt4j@130.60.247.23:httpdocs/
```

Адрес в команде обязателен: без него сайт будет стучаться на старый сервер.

## Каждый раз: новый текст приходит от лингвистов

### 1. Локально: проверить и импортировать

Файл от лингвистов кладём в `data/input/annotations/` и запускаем:

```
docker compose exec api python manage.py upload_transcription /data/input/annotations/ИМЯ_ФАЙЛА.xlsx
```

Команда сама проверит файл, импортирует его и запишет готовые CSV в
`data/php_ready/`. Если в файле ошибки — ничего не импортируется и все
проблемы выводятся списком.

### 2. Залить два файла на сервер

Для нового текста меняются ровно два файла:

```
scp data/php_ready/sentences/ИМЯ_ТЕКСТА.csv languagesofthebalkan_hexru0kbt4j@130.60.247.23:private/data/sentences/
scp data/php_ready/tokens/ИМЯ_ТЕКСТА.csv languagesofthebalkan_hexru0kbt4j@130.60.247.23:private/data/tokens/
```

### 3. Запустить загрузчик

По SSH:

```
php private/sql/import.php --text ИМЯ_ТЕКСТА
```

Загрузчик удалит из базы старую разметку этого текста и вставит новую. Другие
тексты он не трогает.

**Если команды `php` в консоли нет** (так бывает на этом хостинге, потому что
SSH в «клетке»): в панели Plesk есть **Запланированные задачи**. Создать задачу
типа «Запустить PHP-скрипт», указать `private/sql/import.php`, и нажимать
«Выполнить сейчас» — работает так же.

## Когда меняются метаданные

Если правились таблицы говорящих или текстов — файлов три, и текст трогать не
нужно:

```
scp data/php_ready/speakers.csv data/php_ready/texts.csv data/php_ready/text_authors.csv \
    languagesofthebalkan_hexru0kbt4j@130.60.247.23:private/data/
```

И затем:

```
php private/sql/import.php --metadata
```

---

## Три правила, чтобы ничего не сломать

1. **Файлы в `php_ready/` руками не правим.** Они создаются командой импорта.
   Исправлять нужно исходный xlsx и импортировать заново.

2. **Не заливаем пустой файл текста.** Загрузчик заменяет разметку текста
   содержимым файла, поэтому пустой файл её сотрёт. Команда экспорта такой
   файл не создаёт специально, но если он откуда-то взялся — не заливать.

3. **Пароль от базы только в `private/config.php`.** Не в коде, не в git, не в
   переписке.

## Если что-то не работает

| Что видно | Где смотреть |
|---|---|
| Сайт открылся, но пустой, ничего не находит | адрес API при сборке — шаг 6 |
| «Connection refused» при загрузке | сервер не видит `mariadb.uzh.ch:3310` |
| Вместо букв «Ð¿Ð°Ð½Ð¾Ð²» | кодировка таблиц — должна быть `utf8mb4` |
| Поиск не находит слово с заглавной буквы | сравнение таблиц — должно быть `utf8mb4_unicode_ci` |
| 404 на `/api/v1/texts/` | файл лежит не как `api/v1/texts/index.php` |
